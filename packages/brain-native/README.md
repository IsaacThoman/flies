# brain-native

Historical timings and trial counts have [measurement provenance](../../docs/measurements.md).

The TypeScript model in `packages/brain`, implemented in C++20 for the Apple TV and browser WebAssembly. The shared harness checks matching spikes, commands, rates and state digests against Node on the supported platform. Input precision and engine math limit that agreement; see [where it can differ](#where-it-cant-be-the-same) and [the workflow](#when-the-model-changes).

The interface is `include/fly_brain.h`, plain C: build a brain from the bytes of `connectome.bin`, ask it where each facet of its eyes looks, tick it with senses and what each facet sees, get commands, stats and the readout rates back. Creation and tick catch exceptions, returning an error message when the caller supplies a nonempty buffer. Callers must still provide valid handles, pointers and buffer lengths; invalid memory access is outside that error contract. One brain is used from one thread at a time. The standard library is the only dependency.

`packages/brain/README.md` is the reference for the model itself. Everything here follows it; nothing about the model is decided here.

## Using it in an app

Compile every `.cpp` in `src/` into the app, with `src/` and `include/` on the header path, as C++20. `src/` holds the library and nothing else; the comparison harness and the benchmark are in `tools/`.

`fly_brain_rate_count()` is 84 on the real connectome, not 9: the nine readouts the commands come from, then the 63 `region.<id>` rates (display only; always all of them, so they start at index 9 whatever the connectome), then six `vision.<stage>` groups per eye (display only). Size the `rates` buffer from it. Light is `fly_brain_facets()` floats per eye (880 left, 892 right), in the order of `fly_brain_eye_directions()`.

- **Optimise with -O2** (or -O3, which measures the same). Xcode's Release default, -Os, is about 20% slower here.
- **No fast math** (Xcode's *Relax IEEE Compliance*); `src/exact.hpp` refuses to compile with it. And no `-ffp-contract=fast`, which overrides the pragmas below. Nothing else about floating point needs setting: the sources set it themselves. `build.sh` deliberately passes no floating-point flags, so the tests show that.
- Exceptions on (the default); the C creation and tick entry points catch them.

## How it gets the same answers

The TypeScript keeps neuron state in `Float32Array`s and computes in doubles, every operation rounded once, in a fixed order. C++ does exactly that, given a few things, all of which this code does:

1. **Every expression is the TypeScript's, operation for operation**, loading floats into doubles, computing in double and rounding to float on store, never rearranged. That includes the less obvious ones: `a × decay + step` with `decay` and `step` doubles rather than floats; `decayed × keepDrive + 0`, which turns −0 into 0; comparisons made on the double before it is stored (`next >= threshold`) or on the stored float (the rest cut), as sim.ts makes them.
2. **No fused multiply-adds.** JavaScript never fuses; clang does by default on arm64 (`-ffp-contract=on`), which rounds once where JavaScript rounds twice. `#pragma STDC FP_CONTRACT OFF` in `src/exact.hpp`, included first by every file, turns that off with the supported flags above, and `tests/build.test.ts` checks the compiled objects for fused instructions.
3. **V8's own math.** `Math.exp`, `log`, `log1p`, `expm1`, `sin` and `cos` (every transcendental the brain calls: the saturation table, step and chunk decays, smoothing, Poisson probabilities and gaps, Box-Muller, the logistic) are not specified to the bit by JavaScript, and the platform's libm differs from V8's in the last bit often enough to matter. `src/fdlibm.cpp` is V8's port of fdlibm, copied from the V8 that Node 26 ships (14.6, `src/base/ieee754.cc`, BSD-licensed with Sun's fdlibm notice; both kept in the file) with only mechanical changes.
4. **That file, alone, is compiled with contraction on**, because V8 is: Node builds V8 with clang's default, so on arm64 its `Math.sin` and `Math.cos` contain fused multiply-adds, and about one result in fifty differs in the last bit from the same source compiled without. With the pragma, clang fuses the same operations V8's build did; on a machine without fused multiply-adds (x86-64 without `-mfma`) neither fuses. `tests/math.test.ts` holds all six functions to V8's on about 340,000 arguments.
5. **The random streams are integers**: `mulberry32`, the per-input seeds and the internal state's seed are 32-bit arithmetic, exact in C++; a JavaScript seed maps to `seed | 0`. The uniform numbers are exact multiples of 2⁻³². Box-Muller's `2 × Math.PI × v` is `std::numbers::pi`, the same double.
6. **JavaScript's semantics where C++'s differ**: `Math.round` rounds ties up (`js::round`), `Math.max(0, -0)` is +0 (`js::max`, `js::min`), `clamp` reads NaN and infinities as 0, a Poisson gap is a double that may be infinite, and the chunk loop, `advance`'s carry and the readout rate (`count / neurons / ran × 1000`) are computed in the same order.
7. **One shortcut, proven exact**: delivering a spike adds a float weight to a float drive in single precision, where sim.ts adds in double and rounds. For one addition of two floats these are the same, because a double has more than 2 × 24 + 2 bits (double rounding is innocuous; Figueroa, 1995).
8. **What is free to differ, does**: only the membership of the active set and the order of delivery (ascending presynaptic neuron, then target) affect the numbers, not how the set is kept. Here it is a bitmap swept in index order, so the active set needs no sorting (sim.ts keeps a list and radix-sorts it); the small input/bias tail is sorted for merging; the spikes of a step come out ascending and only the few from inputs and biased neurons are merged in. The engine test holds it to sim.ts.
9. **The loader is format.ts's**, following its checks, order and messages for the supported format, including how JavaScript reads odd headers: `JSON.parse`'s grammar (with surrogate pairs, duplicate keys taking the last, arbitrary nesting without recursion, numbers parsed correctly rounded without the C locale's decimal point), `TextDecoder`'s strict UTF-8 and its dropping of a byte order mark, JavaScript truthiness of a section entry, and template-literal printing of wrong values ("`type is u16,,1.5e+300`"). format.ts reads past the last connection as `undefined` when `ptr` overshoots; this loader stops at the last one, which ends the same way (ptr must then decrease, and that is reported). The bytes are read in place, little-endian on any machine and at any alignment. Invalid JSON uses `not valid JSON: <reason> at byte n` here and V8's own parser message there. Native code also rejects counts exceeding its 32-bit storage.
10. **The eyes' data is the TypeScript's.** The column table is generated from `../brain/src/eye-columns.ts` into `src/eye_columns.cpp` (`scripts/eye-columns.ts`), and a test regenerates it and fails if the file differs. Facet directions are computed as eyes.ts does, with V8's `sin` and `cos` and `Math.hypot` as V8 implements it (`js::hypot`: both scaled by the larger, Kahan-summed squares, `sqrt`; held to `Math.hypot` on 96,661 pairs, including 90,000 random pairs; for these arguments even a plain square root of the sum gives the same floats, so the port is exact with room to spare), then rounded to float as `Float32Array.set` rounds. The patterns that pick cells by type (params.ts's columnar classes, the vision stages' `/^T[45][a-d]$/` and `/^(LC|LPLC|LLPC|LPC)\d/`) are written out by hand and held to the regular expressions on every type in the data, near misses and 20,000 random strings.
11. **The retina and the rated input are line for line**: the levels in double, `Math.min(1, x)` for a luminance with NaN read as 0, the idle shortcut's catch-up `x + (before + (level - before) × e^(-idle/τ) - x) × e^(-dt/τ)` in that order, and the thinning sampler's draws in the same order (the keep draw, then the next gap), since every draw moves the stream.
12. **Factors on the gains are derived as the TypeScript derives them**: Johnston's organ's completeness factors (params.ts's `completenessFactors`, `completeness()` here) sum each zone's raw synapse counts per side, exact as integers in both, and divide in double; each factor, like the graded relays', is applied as the float gain times the double factor, rounded to float.

### Where it can't be the same

- **Senses arrive as floats.** `fly_senses` holds single-precision intensities (and hunger), and the TypeScript takes doubles. An intensity of 0.4 is a different number in each, and so a different firing rate, so identical trajectories are no longer guaranteed; individual spikes may still match. The comparison feeds both builds the same float values. A host that wants its fly to match a browser's for the same game state should send float-representable intensities (or the header could take doubles).
- **Light is floats on both sides**, so nothing is lost there: the game hands the TypeScript `Float32Array`s (`apps/web/src/life.ts`), the C interface takes floats, and the same frame is the same bits in both. Only a host that gave the TypeScript plain arrays of doubles would see it part from this, as with the senses.
- **Light the C interface can't express.** It reads `fly_brain_facets()` floats from each pointer, so an array of the wrong length has no counterpart; it is up to the caller. What it can express matches: one pointer NULL is an eye left out, refused with runtime.ts's message ("The left eye has 880 facets, but the light gives undefined"), and both NULL is the eyes shut. The TypeScript's refusal of wrong lengths, and of `light: {}` (both eyes left out, which the C interface can only mean as shut), are ported in `fly::Brain::tick` and compared through the harness, which calls it directly for those ticks.
- **Other JavaScript engines need not agree with Node.** JavaScript does not specify transcendental math to the last bit. This port targets the Node math used by the supported parity checks, rather than promising equality with every browser engine or Node build. A last-bit rate or normal-deviate difference can change a geometric gap or an acceptance decision, and can change a reported rate even while spikes still match. No bound on the time until trajectories diverge is established here.

## How it is tested

`npm test` runs `tests/*.test.ts` with the rest of the repository; `node --test 'packages/brain-native/tests/*.test.ts'` runs just these, in a minute or two. They build the library first (`build.sh`, a no-op when nothing changed) and skip, saying why, when there is no compiler; the real-connectome tests also skip without `packages/brain/data/connectome.bin`. Shared harness and math comparisons run twice: with the native harness, and with the same harness built as WebAssembly (`wasm/fly-brain-harness.wasm`, committed), run in the test's own Node under WASI, which needs no compiler (see "In a browser"). Generated-source, native sanitizer/object and browser-wrapper checks have their own platform-specific paths.

Both builds write the same line per tick (`tests/compare.ts` from the TypeScript, `tools/harness.cpp` from the native brain, through the C interface): spikes, active neurons, simulated time, the eight commands and every rate (the regions and the vision groups included) as doubles and as the C interface's floats, the internal background's three processes and sleep term, a digest of both retinas' rates, and every 50 ticks a digest of every neuron's v, g and a. Numbers are written as the hex of their bits. Equal lines establish equality of those reported values and digests; finite 32-bit digests are not proof that every unreported state value is equal. The light goes to the harness as a file of the very `Float32Array`s the TypeScript was given.

The scripted senses (`scenario()`) run in cycles. Each starts with an eyes-shut section (about 64 s of nominal valid-range
ticks in the current generated real-eye cycle): rest standing and airborne, each sense alone at full strength, ramps and wavering intensities, held and dragged, sweet while touched, sweet just after a meal and weak sugar as hunger rises (`hunger`, which scales the sweet neurons' output gain and adds to the internal state's arousal), NaN, infinite and out-of-range hunger, looming on both sides, everything at once, a looming pulse every second, random ticks of 0 to 50 ms with random senses, ticks of 0, 0.25 and 0.4 ms, of 7.3, 100 and 1000 ms, out-of-range, infinite and NaN intensities, and invalid ticks, which both must refuse with the same message. The dark section also covers clock and sleep state, sleep gating and
out-of-range internal-state values. Then, given eyes, about 58 nominal seconds with them open (`sight()`), the light rendered by `packages/brain/src/stimuli.ts` for the brain's own eye map: a steady grey scene, a steady checkerboard appearing, every stimulus of the battery from its steady ground (looms fast, slow, at either eye, the front and above, a receding disc, dimming and brightening, bars and dots four ways, gratings four ways in one eye and rotating around both, flicker, the checkerboard), the eyes toggling every 5 ticks during a loom and shutting/reopening in separate grating phases, a grating with both looms, touch, both antenna bumps, wind and sweet at full strength, a loom while held and dragged, flicker while sweet, sleepy eye gain and waking transitions, a bar with random senses, NaN, infinite, negative, above-1 and subnormal luminances mixed at random and each over the whole field, random luminances, odd luminances with out-of-range senses, light over 1000, 100, 7.3, 0.25 and 0 ms ticks, a steady scene held for three seconds and then changed (the retina's idle catch-up), and light that doesn't fit: an eye's array a facet short, a facet long or empty, either eye left out, both left out, and an invalid tick with it, each refused with the same message and the brain unchanged after.

## Building

```sh
packages/brain-native/build.sh            # build/release: libflybrain.a, fly-brain-harness, fly-brain-bench
packages/brain-native/build.sh sanitize   # build/sanitize: the same with ASan and UBSan
```

`clang++` from the Xcode command line tools is all it takes (`CXX` picks another compiler). The harness's modes are described at the top of `tools/harness.cpp`.

## In a browser: WebAssembly

The same sources, built as WebAssembly, are the brain a browser runs wherever it can (apps/web/src/brain/, docs/web.md): `wasm/fly-brain.wasm`, [dated artifact sizes](../../docs/measurements.md#artifact-sizes), behind the C interface, and `wasm/brain.ts`, which wraps it as packages/brain's `Brain`, so the browser's worker runs one or the other unchanged.

```sh
npm run brain:wasm                         # wasm.sh: wasm/fly-brain.wasm, wasm/fly-brain-harness.wasm, wasm/build.json
packages/brain-native/wasm.sh --check      # builds into build/wasm/ and fails unless that is what wasm/ holds
```

- **The toolchain is wasi-sdk 34** (clang and wasm-ld of LLVM 23, wasi-libc, and libc++ built with WebAssembly's exceptions): one archive per host (180 MB) that `wasm.sh` downloads once into `build/` and checks against its digest, nothing to install, no Python, no JavaScript glue; `WASI_SDK_PATH` uses another copy. Emscripten would give the same code with a JavaScript runtime and a multi-gigabyte SDK to maintain; this module imports seven WASI calls (an empty environment, the clock, and a stderr only an abort writes to), which `wasm/brain.ts` answers in forty lines. Apple's clang has the WebAssembly back end but no linker or C library for it.
- **The modules are committed**, so `npm install` and `npm run build` need no WebAssembly toolchain. `npm test` uses the committed modules; an available native compiler still builds the native comparisons, and wasi-sdk enables the optional reproduction check. CI has no mandatory module-build step. `wasm/build.json` holds the digest of every source and of the modules: `tests/wasm.test.ts` fails as soon as a source changes without them being rebuilt, and, where wasi-sdk is present, `tests/build.test.ts` rebuilds them and requires the same bytes. They are deterministic for a toolchain and sources; whether every host's wasi-sdk makes the same bytes (arm64 macOS made these) hasn't been checked.
- **Exceptions are WebAssembly's own**, in the standard form (`exnref`), which is how wasi-sdk's libc++ is built. The library throws to report bad data and refusals, as on the TV; `wasmBrainSupported()` validates a two-instruction module that needs it, and a browser without it gets the TypeScript brain.
- **Exactness.** Everything above holds as it is: WebAssembly's floating point is IEEE double and single precision, each operation rounded once, with no fused multiply-add, no excess precision and no fast math, so the rest of the brain compiles to the very operations it does natively. The exception is V8's math (`src/fdlibm.cpp`), which is Node's only with the fused multiply-adds arm64 gives it. WebAssembly has none, and clang would split each contracted multiply-add in two; `wasm.sh` compiles that one file to LLVM IR and turns each `llvm.fmuladd` into `llvm.fma`, which becomes a call to wasi-libc's `fma`, computed in software and correctly rounded: one rounding, as the instruction does. So the WebAssembly brain is the arm64 brain, the Apple TV's, bit for bit, in any engine on any machine (it is no longer at the mercy of the engine's `Math`, as the TypeScript is: see "Where it can't be the same" above). The software `fma` (with its `scalbn`) took about 7% of the time in a profile of rest, every sense and a grating.
- **The connectome is written straight into the module's memory**: `WasmBrainModule.connectomeSpace(bytes)` mallocs room for it, the worker's decoder (apps/web/src/brain/wire.ts) unzips into that, and `create()` builds the brain and frees it. No copy of the 40 MB is made in JavaScript. A WebAssembly memory never shrinks, so the freed 40 MB remains within its capacity and can be reused by the allocator: a current instantiation uses 99,680,256 bytes (95.0625 MiB) of linear memory. The earlier TypeScript comparison was about 180 MB; its capture metadata was not retained.
- **Tested** as above: shared harness comparisons run `wasm/fly-brain-harness.wasm` too, in Node's WASI, compared line for line with the TypeScript, internal state, retinas and the digest of every neuron included; and `tests/wasm.test.ts` runs the shipped module through `wasm/brain.ts`.
- **What it differs in, as the TV's brain does**: the senses and the commands and rates cross the C interface as floats, where the TypeScript keeps doubles (see "Where it can't be the same"). The eyes' acceptance is the TypeScript's double rounded to a float.

## Speed and memory

Wall time per simulated second on an Apple M5 Pro, one thread, the real connectome, fixed 16 ms benchmark ticks (the game sends variable elapsed time), after a simulated second untimed (`node packages/brain-native/scripts/bench.ts`, which runs both on the same senses and the very same light frames, rendered from `../brain/src/stimuli.ts` as `../brain/scripts/report.ts` (e) has them; `-O2`, the release build):

| Regime | Active neurons | Spikes per second | TypeScript (Node 26) | Native | |
|---|---|---|---|---|---|
| At rest, standing, eyes shut | ~40,000 | ~23,000 | 0.09 s | 0.052 s | 1.8× |
| Every sense at full strength, eyes shut | ~92,000 | ~512,000 | 0.30 s | 0.153 s | 1.9× |
| A steady uniform scene | ~58,000 | ~37,000 | 0.12–0.14 s | 0.067–0.074 s | 1.8× |
| A disc looming at the right eye, over and over | ~86,000 | ~286,000 | 0.20–0.24 s | 0.109–0.120 s | 1.9× |
| A grating drifting across both eyes (the worst case) | ~124,000 | ~970,000 | 0.37–0.46 s | 0.205–0.225 s | 1.8–2.0× |
| The whole field flickering at 4 Hz | ~125,000 | ~744,000 | 0.32–0.39 s | 0.19–0.24 s | 1.7× |

The ranges are repeated runs on a machine others were using. The first two rows and the counts were measured again when `grounded` was narrowed to the legs' load sensors and `wingbeat` added (packages/brain/README.md, Senses), one run on a busy machine: at rest the brain had been firing ~49,000 spikes a second with ~58,000 neurons active, the wings' and halteres' sensors driven while it stood; every sense now includes `wingbeat`. The regions' readout changes none of these beyond that spread (packages/brain/README.md, Regions, Cost). Both builds report the same active neurons and spikes in each regime, as they should (a spike rate ending in .5 is printed rounded up by the TypeScript and to even here). Building the brain takes about 45 ms (the TypeScript's, 120 to 140 ms).

Memory: the brain takes 58 MB (with what building it uses; the file the host read is another 40 MB and need not be kept), and the most the process ever holds is that and the file, 98 MB, measured as the system's own peak footprint. 50 MB of it is the connections, a target and a weight each; per-neuron state, the CSR pointers, the spike ring and the readouts make the rest. The eyes add next to nothing (the column table, two retinas of about 2,600 cells, and the vision readouts' entries in the neuron-to-readout lists), and the regions a byte a neuron (167 kB). The TypeScript brain's process is about 180 MB (the bench's 197 to 201 MB, less the 19 MB of frames it keeps for the native run).

On the Apple TV these are estimates, not measurements: an A15 core is roughly half an M5 Pro's, which puts the brain at about 0.13 s per simulated second at rest or in a steady scene, 0.25 s with every sense at once or a loom, and 0.45 s for the grating across both eyes, 13 to 45% of a core; an A10X core roughly a third, 0.2 to 0.65 s, still within real time but with little room in the worst case.

Where the time goes (sampled): at rest three quarters of it is the sweep over active neurons, with everything on about 60%, and a third is delivering spikes. Under the grating, the sweep is 63% and delivering spikes and the inputs 29%; the vision path itself is small: the rated input's draws, with their `log`, 6%, sorting the input spikes into the step's ascending list 1.7%, the retina 0.5%. The draws are what the TypeScript draws, one or two per candidate spike, and the stream has to move exactly as it does, so they stay; what costs under vision is the optic lobe answering, as in the TypeScript (its README, Cost). The sweep compiles to about 27 instructions a neuron and runs at about 4 cycles: it is bound by the double-precision arithmetic itself, which is what exactness requires. What was tried:

- **Kept**: the bitmap active set (no sorting; sweeps in index order); state interleaved 16 bytes a neuron; connections stored as interleaved target and weight; muted neurons' spikes skipped; prefetching each spike's connections a few spikes ahead (5% with everything on, 2% at rest, and probably more on the TV's smaller caches).
- **No gain**: a branch-free join on delivery (slower: it chains stores to the same word), the drive in its own array (slower), -O3 (the same as -O2), and a vectorised sweep over a dense layout (in isolation 0.82 against 0.88 ns a neuron: two doubles a vector buys little, and it would cost an indirection on every delivery).

What more speed would cost:

- **Threads.** The sweep and delivery split cleanly by neuron and the result can be kept exact (each neuron's sum stays in delivery order if each thread owns a range of targets), but it means a worker pool next to the renderer and per-step synchronisation about a thousand times a second.
- **Single precision.** Computing in floats would roughly halve the sweep's cost and vectorise four-wide, and end the agreement with the TypeScript: the TypeScript would have to change first, and the browser would pay for it in `Math.fround` calls.
- **4-byte connections** (target and saturated count packed, the weight looked up per presynaptic gain) would save 25 MB and some delivery bandwidth, for a more specialised layout tied to the operating point.
- **A dimmer lamina.** The TypeScript's README notes that halving `RETINA.maxRate` halves the spikes a rotating grating causes, at the price of most of the motion pathway; that would change the model in both `packages/brain` and `packages/brain-native`.

## The eyes

The TypeScript's eyes (packages/brain/README.md, The eyes and Seeing), ported:

- **The map** (`src/eyes.cpp`, eyes.ts): each eye's columns from `src/eye_columns.cpp`, 880 left and 892 right, resolved to neuron indices by body ID (`Connectome::index_of`, format.ts's `indexOf`), with eyes.ts's check that each is an L1, L2 or L3 of the right side and its message, in the same order (left eye first, every L1, then every L2, then every L3), and no eyes when no L1 resolves. `fly_brain_facets`, `fly_brain_eye_directions` and `fly_brain_eye_acceptance` give the map (0, NULL and 0 without eyes); the acceptance is the TypeScript's double rounded to float.
- **The table** is generated, not copied: `node packages/brain-native/scripts/eye-columns.ts` rewrites `src/eye_columns.cpp` from `packages/brain/src/eye-columns.ts` (`--check` only checks), and `tests/eyes.test.ts` fails while the two differ, so a new table in the TypeScript can't go unnoticed here.
- **The columnar relays' graded synapses** (`src/params.cpp`, params.ts's `graded` and `columnar`): the gain of every optic lobe intrinsic neuron of a columnar class with at least 100 cells of its type on its side, times 2.3, rounded to float as `gain[i] *= graded` rounds it; counted by type and side strings, as params.ts counts them.
- **The rated input** (`src/sim.cpp`, sim.ts's `RatedPoissonInput`, `addRatedInput`, `setRates`): a rate per neuron, drawn by thinning, with the same checks and messages. Inputs now say whether they are on, as sim.ts's do.
- **The retina** (`src/vision.cpp`, vision.ts's `Retina`): adaptation, contrast and the transient and sustained cells, the idle shortcut for an unchanging scene, opening adapted.
- **The brain** (`src/brain.cpp`, runtime.ts): the retinas' rated inputs in the [reference input order](../brain/README.md#seeing), the check that no lamina cell is read, the `vision.<stage>` readouts after the nine neural readouts and the regions (each eye's lamina, medulla, T4/T5, lobula, looming and tangential groups, those with any cells), smoothed over 100 ms; and per tick, the light checked before anything moves, then each 10 ms chunk the retinas stepped after the background rates and their rates passed on when they changed, as runtime.ts does.

The custom columns runtime.ts takes for tests (`eyeColumns`) are `fly::Brain`'s third argument; the harness reads them from a file. The C interface always uses eye-columns.ts's table, as `createBrain` does.

## The regions

regions.ts's catalog of the nervous system by region (packages/brain/README.md, Regions), ported:

- **The rules** (`src/regions.cpp`, regions.ts's `regionIdOf`): the same checks in the same order, on the super class, class, sub class, type and soma side strings. JavaScript compares UTF-16 strings and this compares UTF-8 ones; every string the rules compare with is ASCII, and an ASCII string equals, or is a prefix of, another in UTF-8 exactly when it does in UTF-16. The ids are written out in the catalog's order. The names, descriptions, places and display scales are the TypeScript's only: nothing here needs them.
- **The partition** (`src/sim.cpp`, sim.ts's `setPartition` and `drainPartition`): each neuron's region as a byte, and one count a spike, after the readouts are counted.
- **The rates** (`src/brain.cpp`): every region, after the nine readouts and before the vision stages, smoothed over 100 ms each 10 ms chunk as runtime.ts smooths them, the count over the region's size over the time run, times 1000; an empty region stays at 0.

## When the model changes

The model is developed directly in this repository. `packages/brain` is the TypeScript reference; keep this native implementation equivalent when changing it:

1. Port the change into the file of the same name: `src/params.cpp` for the operating point, `src/io.cpp` for groups, scales and decoding, `src/state.cpp`, `src/sim.cpp`, `src/eyes.cpp`, `src/vision.cpp`, `src/regions.cpp`, `src/brain.cpp` for runtime.ts, `src/connectome.cpp` for format.ts. A new eye table: `node packages/brain-native/scripts/eye-columns.ts`. Write each expression as the TypeScript writes it, in the same order, doubles from floats. Keep the TypeScript's comments' substance.
2. A new `Math` function: take it from the same upstream `src/base/ieee754.cc` into `src/fdlibm.cpp` and add it to `tests/math.test.ts`. Never `<cmath>`'s, except `sqrt`, `floor`, `trunc` and `fabs`, under the supported IEEE toolchain: `sqrt` is correctly rounded, and the other three are exact on their finite representable-domain operations.
3. `npm run brain:wasm` and commit `wasm/`: the WebAssembly build is committed, and `tests/wasm.test.ts` fails while its sources differ from what it was built from.
4. Run the exact-comparison tests on the reference platform: Apple-silicon
   macOS Node (CI currently uses Node 24). Other JavaScript engines and
   x86/Linux builds can differ in their last-bit math; see [parity limits](#where-it-cant-be-the-same).
   Run the tests. If a comparison fails, the message names the first tick that differs and what was happening; the engine test narrows it to a step and a neuron. Extend the scenario if the change adds something it doesn't exercise.
5. When Node's V8 moves to a new version, run `tests/math.test.ts`: if V8 changed its math, copy the routines again from that version.

## Found in the TypeScript

Not fixed there (that is for `packages/brain`), and matched here:

- The internal state's normal deviates come from `Math.sin` and `Math.cos` (Box-Muller), whose last bits can differ between engines, so a shared seed alone does not promise identical browser and Node trajectories. Marsaglia's polar method would need only `Math.log` and `Math.sqrt`; its exact result would still depend on engine math, which JavaScript does not specify to the bit.
- Left/right balancing (`../brain/src/io.ts`, `balanceFactor`) counts the raw synapses, while the network uses the saturated counts, so at full strength the two sides deliver the same raw synapse-spikes, not quite the same effective ones as the README says.
- `loadConnectome` reads past the last connection, as `undefined`, when `ptr` overshoots before coming back; harmless, since a later decrease is always reported, but it is a read out of bounds that only JavaScript forgives.
- **With the eyes shut the brain is not quite what it was before it had eyes** (its README and `../brain/src/seeing.test.ts` said it was when this was found, and have been corrected). The graded columnar synapses apply with the eyes shut too, and a columnar cell can fire without light: in this repository's scripted senses (`scenario()` in `tests/compare.ts`, seed 1), after 3 s at rest, 1 s airborne, `loomLeft` 1.5 s and 0.8 s of rest, a TmY17 of the right eye fires once under `loomRight` at full strength, and at tick 446 the brain fires 2,725 spikes against 2,732 with `graded: 1`. The fingerprint test only drives `loomLeft`, touch and wind, and sweet and `bumpRight`, which happen not to reach one. (It was found as this port's comparison, still on the model before the eyes, failing at that tick.)
